# Prune Plugydown Context

Load the Context Operating Skill first and follow its Runtime, status, Role Brief, approval, and reporting rules.

1. Call `repository.inspect`; continue only from structurally ready Context with readable sources or resume the active run. Prune is always
   Deep. Check confirmations in the affected scope; unmatched inputs require evidence review, not a Repair step.
2. Call `growth.measure`. Treat duplicate, fragmented, orphaned, and concentrated results only as review candidates.
3. An Investigator verifies unique constraints, decisions, procedures, Reflections, relations, and hard source
   coverage. Every merge, move, rewrite, split, or deletion needs an explicit survival location.
4. Begin `prune/deep`. Give one Recorder a `converge` Role Brief and allow writes only in the complete candidate. Do
   not create an archive, remove content merely by age, or promote Feedback.
5. Validate the candidate and compare explainable before/after metrics. An Investigator performs semantic review; the
   Main Assistant approves the unchanged candidate/source fingerprints and commits.
6. Report status, scope, each convergence change, preserved coverage, before/after metrics, fingerprints, validation,
   review, commit, and recovery outcome. Unaccounted unique knowledge makes the result `incomplete`.

Prune updates the convergence baseline only. It retains historical confirmation files, even for deleted Documents; it
does not turn unrelated unmatched inputs into confirmed ones or advance the repository baseline.
